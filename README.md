# 온톨로지 기반 금융상품 질의응답 에이전트

> 자연어 금융 질문을 국내 채권 · 국내/해외 ETF · 공모펀드 마스터에 대한 SQL 조회로 옮겨 **근거와 함께** 답하는 에이전트.
> 제10회 미래에셋증권 AI Festival(2026) 주제 1 — 금융상품 Agent 출품작.

```
"커버드콜 ETF 중에 분배율 높은 3개 알려줘"
  → 의도 분석(HCX) → 상품군 판정 → 값 접지 → 답변가능 판정
  → SQL 생성(HCX) → 가드 검사·교정 → 실행 → 답변 조립
  → { question_id, question, retrieved_context, think_trace, answer }
```

| | |
| :-- | :-- |
| 기간 | 2026.08 ~ 09 (약 5주) |
| 팀 | **3인** — 리드·펀드 / 채권 / **ETF·외부데이터(본인)** |
| 데이터 | 주최 제공 마스터 4테이블 53,375행 (기준일 2026-08-22) + 자체 수집 약 105만 행 |

### 역할 분담

세 사람이 **도메인을 하나씩** 맡고, 파이프라인 본체(`src/runtime/`)는 공유했습니다. 남의 도메인 파일은 건드리지 않고 필요하면 요청하는 규칙으로 작업했습니다.

| 담당 | 범위 |
| :-- | :-- |
| 리드 · 펀드 | 공모펀드 도메인 · 지식그래프 빌더 · 배포 · 기술제안서 조판 |
| 채권 | 국내채권 도메인 · API 명세 · 기대효과 절 |
| **ETF · 외부데이터 (본인)** | **국내/해외 ETF 도메인 전체 · ETF 가드와 회귀 테스트 · 구성종목 외부 수집과 적재** |

아래 3절의 실패 분석은 제가 맡은 ETF 트랙 기록입니다. 나머지 코드와 문서는 팀 공동 산출물입니다.

## 1. 무엇이 어려운 문제였나

질문에 답하는 것 자체는 어렵지 않습니다. **틀리게 답하지 않는 것**이 어렵습니다.

금융 상품 데이터에는 함정이 많습니다.

- 총보수 `0`은 "수수료 무료"가 아니라 **미입력**입니다. 그대로 정렬하면 "가장 싼 상품"이 됩니다.
- **자금 유출입 컬럼이 없습니다.** "돈이 몰리는 ETF"를 물으면 모델은 거래대금을 대신 가져다 씁니다. 사고판 금액과 들어온 금액은 다른 값입니다.
- 분배주기는 `M`·`Q`·`S`·`A`라는 **글자**입니다. 내림차순으로 정렬하면 알파벳 역순이라 반기 지급이 1등이 됩니다.

세 경우 모두 **답에 나온 숫자는 전부 데이터베이스에 실재하는 값**입니다. 할루시네이션 검사에도, 값 대조 검사에도 걸리지 않습니다. 그래서 검사로는 못 잡고 **판정 구조**로 막아야 합니다.

## 2. 어떻게 풀었나

### 판단 기준을 코드가 아니라 선언에 두었다

도메인 규칙을 `ontology/enums/*.yaml` 한 곳에 모았습니다. 컬럼의 의미, 조회 기본 모수, 되묻기 조건, 그리고 **"이 데이터에 없는 축"** 을 선언합니다.

```yaml
absent_properties:
  - property: hasFundFlow
    why: "ETF 의 자금 유출입(설정·환매 금액)은 수록되어 있지 않습니다.
          순자산은 기준일 한 시점의 값이라 증감을 계산할 수 없고,
          거래대금은 사고판 금액이라 유입액과 다릅니다."
    vocab: ["자금[ ]?(?:유입|유출|유출입)", "(?:자금|돈)이.{0,12}?(?:몰리|몰린|빠져)"]
```

이렇게 선언하면 해당 질문은 **SQL 을 만들기 전에 끊깁니다.** 모델이 비슷한 컬럼으로 둘러댈 기회 자체를 없애는 방식입니다. 네 도메인에 부재 축 20여 개를 선언했습니다.

### 모델이 만든 SQL 을 그대로 믿지 않는다

언어모델이 생성한 조회식을 실행 전에 검사하고 교정하는 **가드 체인**을 두었습니다. 규칙마다 ① 정답 케이스 회귀 테스트와 ② 손대지 말아야 할 경우(불개입 조건)를 함께 붙였습니다. 가드가 새로운 오류의 원천이 되는 것을 막기 위해서입니다.

### 개수·순위·목록은 코드가 조립한다

집계와 랭킹 답변은 언어모델을 거치지 않고 조회 결과를 그대로 옮깁니다. 숫자를 다시 쓰게 하면 틀릴 자리가 생기기 때문입니다.

### 마스터 데이터는 고치지 않는다

구성종목처럼 제공 데이터에 없는 축은 외부에서 수집해 `ext_*` 테이블로 따로 적재하고 출처·기준일을 붙였습니다. 원본 값을 덮어쓰지 않고 **보강만** 합니다.

## 3. 실패 기록 — ETF 트랙 (본인 담당)

서버에 20문항을 던지고 채점하고 원인을 분해하는 일을 **17라운드** 반복했습니다. 전 과정을 [`docs/기술제안서/ETF_오답_마스터기록.md`](docs/기술제안서/ETF_오답_마스터기록.md) 에 남겼습니다. 세 가지만 옮깁니다.

### ① 값은 전부 맞는데 순서가 틀렸다

> "순자산 상위 5개 ETF" 답변에서 2·3·4위 순서가 뒤바뀌었다.

원인은 이름 매칭이 **부분일치**여서, `KODEX 200TR` 과 `KODEX 200타겟위클리커버드콜` 이 둘 다 `KODEX 200` 행에 붙은 것이었습니다. 세 항목이 전부 같은 행으로 판정돼 순서 검사가 무의미해졌습니다.

→ 긴 이름부터 맞추고, 한 번 쓴 행은 다시 쓰지 않도록 고쳤습니다.

### ② 한글 상품명을 모델이 영어로 번역했다

> "커버드콜 ETF 중에 분배율 높은 3개" → "해당 상품이 없습니다" (실제로는 62건)

모델이 `pd_nm LIKE '%Covered Call%'` 를 만들었습니다. 국내 상품명은 전부 한글이라 0행입니다. 동의어 사전에 `커버드콜 → 커버드콜` 이 있는데도 번역한 것이라 프롬프트로는 막히지 않았습니다.

→ 상품명 조건이 **데이터에 0건**이고 질문 속 한글 낱말은 실재하면 그 낱말로 되돌리는 가드를 넣었습니다. 리터럴이 한 건이라도 맞으면 손대지 않습니다.

### ③ 정렬 축이 순위를 만들 수 없는 컬럼이었다

> "1년에 배당금 제일 많이 주는 ETF" → 반기(연 2회) 지급 상품이 상위를 차지

`ORDER BY` 대상이 분배주기(`M`·`Q`·`S`·`A`)였습니다. 글자를 정렬하면 글자 순서가 순위가 됩니다.

→ 범주형 문자열 컬럼을 순위 축에서 제외하고, 질문이 "많이·자주·횟수"면 연간 지급 횟수로, "분배율·고배당"이면 분배수익률로 정렬하도록 교정했습니다. 축을 정하지 않은 문장에는 개입하지 않습니다.

> **부수 발견** — 분배**율**(율)과 수익**률**(률)은 다른 글자입니다. 정규식에 한쪽만 적어 '분배율' 질의가 통째로 빠져 있었습니다.

## 4. 남은 한계 — 대회가 끝나고 다시 본 것

**가드가 규칙 목록입니다.** ③을 고칠 때 범주형 컬럼 14개를 목록으로 막았습니다. 대회가 끝난 뒤 *"가장 최근에 배당금을 준 ETF"* 를 던져보니, 이번에는 그 목록에 없던 **분배기준일**(모든 행의 값이 같아 순위가 생기지 않는 컬럼)로 정렬해 또 틀렸습니다.

목록이 아니라 **성질**로 판정했어야 합니다. 조회식을 만들 때 정렬 대상 컬럼의 값 종류가 몇 개인지 확인해서, 서로 다른 값이 거의 없으면 순위 축에서 배제하는 방식입니다. 목록은 겪어본 것만 막고, 성질은 안 겪어본 것도 막습니다.

**시험 문제를 제가 냈습니다.** 20문항을 제가 출제하고 제가 채점했습니다. 파이프라인을 아는 사람이 낸 문제라 제 사각지대는 비추지 못했고, 그래서 라운드마다 새 오류 부류가 계속 나왔습니다. 문항 출제와 수리를 분리했어야 합니다.

**파이프라인 본체가 한 파일에 12,000줄 넘게 쌓였습니다.** 세 도메인이 공유하는 파일이라 마감까지 분리를 미뤘습니다. 구조를 바꾸면 전체 회귀를 다시 돌려야 하는데 배포 창이 하루 몇 번뿐이었습니다. 일정 판단으로는 맞았지만 코드 품질로는 부채입니다.

## 5. 저장소 구성

| 경로 | 내용 |
| :-- | :-- |
| `src/runtime/` | 라우팅 · 값 접지 · 답변가능 판정 · 가드 체인 · 답변 조립 |
| `src/hcx/` | HyperCLOVA X 연동 — 의도 분석 · SQL 계획 · 답변 작성 |
| `src/api/` | FastAPI 서버 (`GET /answer`) |
| `ontology/enums/` | **도메인 규칙 yaml** — 조건식 · 기본 모수 · 되묻기 · 부재 선언의 단일 원천 |
| `ontology/*.ttl` | yaml 에서 생성한 온톨로지 (채권 · 국내ETF · 해외ETF · 펀드) |
| `tests/` | ETF 트랙 회귀 테스트 — 가드마다 정답 케이스와 불개입 조건 |
| `scripts/` | DB · 온톨로지 빌드 · 외부 데이터 수집 · 주장 검증 |
| `eval/` | ETF 평가 문항 |
| `docs/` | 오답 분석 기록 · ETF 도메인 설계 · 온톨로지 엔지니어링 · API 명세 |

### 이 저장소에 대하여

5주간의 작업 저장소에서 **읽을 만한 것만 추렸습니다.** 엔진 전체와 ETF 트랙의 규칙·회귀 테스트·설계 기록, 그리고 재현에 필요한 스크립트입니다.

| 제외 | 이유 |
| :-- | :-- |
| 주최 제공 원본 엑셀 · 산출 DB · 과제 자료 | **배포 제한** |
| 데이터에서 자동 생성한 값 사전(`*_auto.yaml`)과 그 생성물 | 원본 데이터의 다른 표현 |
| 자체 수집 구성종목 원본 CSV | 용량. 수집 방법은 `scripts/fetch_*.py`, 출처·기준일은 [`data/external/holdings/SOURCES.md`](data/external/holdings/SOURCES.md) |
| 팀 내부 작업 문서(인수인계 · 회신 · 라운드 로그 300여 편) | 팀 안에서만 뜻이 통하는 기록 |

문서에 남은 팀원 표기는 **역할명(리드 · 채권 담당 · ETF 담당)으로 바꿨습니다.**

## 6. 실행

```bash
pip install -r requirements.txt

python scripts/build_db.py               # 주최 제공 엑셀 → 마스터 4테이블
python scripts/load_external_holdings.py # 외부 수집분 → ext_* 테이블
python scripts/build_ontology.py         # yaml → 지식그래프 + ttl

uvicorn src.api.main:app --host 0.0.0.0 --port 8000
pytest -q                                # DB 가 필요한 항목은 없으면 자동 skip
```

제출 당시의 서버 운영 정보와 실행 절차는 [`docs/00_제출본_README.md`](docs/00_제출본_README.md) 에 있습니다.
